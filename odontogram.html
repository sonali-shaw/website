3D Odontogram
An interactive 3D dental charting tool built with Three.js, using real scanned tooth morphology models to let you explore each of the 32 adult teeth in three dimensions. A synced 2D dental arch map mirrors the classic odontogram layout, so clicking a tooth in either view highlights it in the other. Built-in landmark annotation and a flashcard-style study mode turn it into a self-quizzing tool for learning tooth anatomy and numbering.
Features
  • Full 3D models for all 32 adult teeth, individually selectable
  • Synced 2D odontogram map with upper/lower arch layout
  • Landmark annotation with JSON export
  • Flashcard mode for self-testing tooth identification
Technical Deep Dive
How the Odontogram Works
3D Scene & Model Loading

All 32 teeth live as separate named meshes inside a single glTF scene, loaded once with Three.js's GLTFLoader and decoded through Draco compression to keep the download size reasonable despite the anatomical detail. A PMREM-prefiltered environment map gives the enamel surfaces realistic reflections instead of flat, unlit shading. Clicking a tooth raycasts against the mesh list to figure out exactly which one was hit, then drives both the 3D highlight and the synced chart from that single source of truth.

Synced 2D Odontogram Chart

The classic dental-chart shape — two open arcs, upper teeth (1–16) and lower teeth (17–32), mirrored and stacked — is generated entirely from angle and radius math, not a static SVG asset. Clicking or hovering either the 3D model or the 2D chart highlights the same tooth in both, since they're driven by the same underlying selection state rather than being two independently maintained views.

Study Modes

Flashcard mode has three quiz styles — identify a highlighted tooth on the full arch, identify an isolated tooth with no position clue (morphology only), and name a marked anatomical landmark. All three pull directly from the same live 3D scene the rest of the app uses, so what you're quizzed on is always exactly what's rendered — not a separate, easier-to-drift-out-of-sync bank of static images.

Robustness
  • Feature-detects WebGL before touching the renderer, and separately catches failures during the first real GPU call (environment prefiltering) — some browsers pass a naive capability check but still can't actually render, so both paths are covered with a clear message instead of a blank page
  • Asset paths resolve relative to Vite's configured base path rather than being hardcoded, so the same code runs unchanged from a local dev server at the domain root or deployed under a GitHub Pages subpath
  • Deploys automatically via a GitHub Actions workflow on every push — no manual build-and-upload step
