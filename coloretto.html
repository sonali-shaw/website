Coloretto
A fully playable, terminal-based implementation of Coloretto, the card-drafting board game — built from the ground up in Python with no game engine or framework, just the rules and a clean object model. Players draw from a shared pool of face-up stacks or take a stack outright, racing to build the highest-scoring hand across the full multi-round game, endgame trigger included.
Highlights
  • Complete rules implementation: card drawing, dynamic face-up stacks, 2–4 player turn order, scoring, and the final-round trigger
  • Object-oriented architecture that cleanly separates game state, players, and I/O — the kind of structure a real multiplayer or GUI version could build on directly
  • Rich-formatted, ASCII-style terminal interface that makes card stacks and hands genuinely readable at a glance, not just a wall of text
  • Defensive input validation throughout, so a mistyped command never corrupts game state
Technical Deep Dive
How Coloretto Works
Game Model

Five small, focused modules instead of one monolithic script: deck.py tracks the card pool and draw pile, stack.py models a single face-up pile with its own fill/take/reset logic, player.py owns a hand and the scoring math, and game.py drives the turn loop — drawing, placing, taking, and cycling whose turn it is — on top of those pieces. Because state lives on the objects themselves rather than in loose global variables, the same classes could back a networked or GUI version without rewriting the rules.

A Custom Terminal Layout Engine

The most interesting part isn't the game rules — it's tile.py, a small 2D grid-composition system built specifically for this project. A Tile is just a 2D array of cells that knows how to combine with another one: add_left, add_below, mirror, and padding let the game compose player hands and card stacks into a single layout, positioned around the table the way they'd sit at a real one (north/south/east/west), entirely at runtime from however many players are in the game. Each cell renders as a rich-colored Unicode block, so the finished table is genuinely colored terminal output, not plain text.
